Chapter 1: Project Objective & Problem Statement

1.1 The Context of Large-Scale Engineering Recruitment

In high-volume recruitment drives conducted across engineering and degree institutions in Andhra Pradesh, recruiters face acute challenges in screening thousands of candidates with integrity, speed, and fairness. Traditional examination and assessment workflows suffer from manual inefficiencies, compromised question papers, uncurated student academic inputs, and widespread malpractice during online tests.

Cognito Tech Hub (as the primary technology and innovation brand) in collaboration with Quantex Intelligence Systems (as the official talent acquisition and assessment partner) commissioned this unified assessment and recruitment platform to eliminate these vulnerabilities and provide a seamless, enterprise-grade evaluation pipeline.

1.2 Critical Problems Addressed

Problem 1: Fragmented & Unverified Academic Registration
Students routinely input arbitrary college names, conflicting branch acronyms, or generic degree streams. This prevents recruiters from accurately segregating candidates by tier, district, and specialization.
Solution: A curated database of recognized Andhra Pradesh institutions, dynamic qualification-dependent course/stream filtering, and mandatory operational preferences.
Problem 2: Anti-Proctoring Cheating in Online Assessments
Candidates frequently cheat during remote or lab tests by switching tabs to search answers on Google/ChatGPT, using dual monitors, taking screenshots to share via messaging apps, or copying and pasting solutions from external IDEs.
Solution: 1280px desktop resolution enforcement, adaptive hardware webcam monitoring with graceful external monitor detection, 3-strike tab switch termination, clipboard copy/paste shielding, and right-click disabling.
Problem 3: Lack of True Automated Coding Sandboxes
Most commercial platforms test coding only with multiple-choice questions or non-executable text boxes. Candidates who can solve algorithmic problems under time constraints cannot be properly differentiated from those who memorize syntax.
Solution: An integrated, multi-language coding editor supporting Python, Java, C++, and JavaScript with real-time compilation and evaluation against 10 test cases (public samples + hidden edge cases).
Problem 4: Chaotic Admin Portals & Premature Result Leaks
Conventional portals either show unranked data or accidentally leak scores to students before recruiter committees verify academic records, leading to candidate disputes and recruiter bottlenecks.
Solution: A dedicated 23-module Admin Command Center with strict Candidate Score Masking, 10-stage evaluation pipeline, and one-click CSV export for recruiters.

3.2 Module 2: Anti-Cheat Hardware Proctoring & Security Architecture

Display Gate 1280px Resolution Enforcement

The examination interface refuses execution on mobile devices, tablets, or partitioned split-screens. Viewports under 1280px are blocked by an immovable hardware modal demanding a full desktop display.

Hardware Sensor Adaptive Webcam Proctor

Automatically detects camera hardware. If webcam is present, live proctoring feeds candidate video. If PC/monitor lacks a webcam, it transitions gracefully to External Display Mode without disqualification.

Anti-Malpractice 3-Strike Tab Interception

Browser visibility API tracks window blur and tab switching. Strike 1 & 2 display modal warnings; Strike 3 immediately auto-submits the assessment and flags the attempt as cancelled.

Content Shield Clipboard & Screenshot Defense

Right-click context menus, Print-Screen keystrokes, Ctrl+C, Ctrl+V, and text selection are intercepted and suppressed across all examination panels.

Chapter 4: Multi-Language Coding Sandbox & Test Case Suite

4.1 Sandbox Specifications

Section 3 features an embedded code development interface supporting Python, Java, C++, and JavaScript. Candidates can toggle between languages, write algorithmic logic, test code against public sample cases, and trigger final submission against hidden evaluation test cases.

4.2 Automated Test Case Scoring Rubric

Each coding problem is worth 20 marks evaluated against 10 individual test cases (2 marks per passed test case):

Test Case # Classification Evaluation Purpose Weightage
TC-1, TC-2 Public Sample Basic input/output correctness visible to candidate for initial debugging. 4 Marks
TC-3, TC-4 Standard Evaluation Nominal functional test cases with random input ranges. 4 Marks
TC-5, TC-6 Boundary / Edge Empty arrays, single-element collections, minimum/maximum integers. 4 Marks
TC-7, TC-8 Performance / Scale Large array sizes ($N \ge 10^5$), asymptotic complexity compliance ($O(N)$ vs $O(N^2)$). 4 Marks
TC-9, TC-10 Negative / Stress Duplicate entries, negative values, null checks, extreme constraints. 4 Marks
